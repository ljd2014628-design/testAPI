# 断言使用手册

断言就是「接口返回的东西是否符合我的预期」。这份手册讲清楚：在哪里配、怎么写、
哪些场景该用哪种写法。

---

## 一、在哪里配

打开接口编辑窗口（列表里双击某行的非名称列，或选中行点「编辑」），
**底部有两个页签：提取变量 / 断言（预期结果）**。切到断言页。

断言表一行一条，六列：

| 列 | 说明 |
|---|---|
| 启用 | 去掉勾这条本次就不校验，行还留着 |
| 目标 | 要检查什么（见下面「目标怎么写」） |
| 比较方式 | 怎么比（下拉选，共 40 多种） |
| 期望值 | 期望是什么（部分比较方式不需要填） |
| 级别 | **必须通过** = 不满足就算失败；**仅警告** = 不满足只提醒，不算失败 |
| 备注 | 给自己看的说明，不参与判断 |

双击单元格修改，回车保存，Tab 跳下一格。

工具栏按钮：

- **从响应选字段**：打开响应树，点中字段自动填路径，不用手写
- **常用断言**：弹出断言库，按场景一键加一组（见第五节）
- **▶ 试跑断言**：拿一份响应把当前断言跑一遍看结论，**不写进执行历史、不影响「较上次」的基线**

## 二、目标怎么写

| 写法 | 含义 | 例子 |
|---|---|---|
| `$.xxx` | 响应 JSON 里的字段 | `$.code`、`$.data.total`、`$.data.list[0].id` |
| `$.a.list[*].b` | 数组里每一项的某个字段，结果是个数组 | `$.data.list[*].couponNo` |
| `状态码` | HTTP 状态码 | 配 `等于 200` |
| `耗时ms` | 本次请求耗时（毫秒） | 配 `小于 3000` |
| `响应文本` | 整个响应体的原文 | 配 `包含 success` |
| `响应头.X` | 某个响应头 | `响应头.Content-Type` 配 `包含 application/json` |

## 三、比较方式速查

### 数值 / 相等

| 比较方式 | 期望值怎么填 | 说明 |
|---|---|---|
| 等于 / 不等于 | `0` | 数字和数字比数值，其余按文本比 |
| 文本等于 | `优惠券A` | 强制转成字符串比，避免 `1` 和 `"1"` 的坑 |
| 约等于 | `100±5` 或 `100~5` | 浮点金额、耗时这类允许误差的 |
| 大于 / 大于等于 / 小于 / 小于等于 | `10` | |
| 介于 | `1~100` | 闭区间 |

### 文本

包含 / 不包含 / 开头是 / 结尾是 / 正则匹配 / 正则不匹配。
正则例子：券号格式 `^CP\d{4}$`，手机号 `^1[3-9]\d{9}$`，日期 `^\d{4}-\d{2}-\d{2}`。

### 存在 / 空值

| 比较方式 | 用途 |
|---|---|
| 存在 / 不存在 | 字段在不在（反向用例常用：失败时不该返回 `$.data.token`） |
| 为空 / 不为空 | 空判定包括 `null`、`""`、`[]`、`{}` |
| 为null / 不为null | 只判 null，区别于空字符串 |

### 类型 / 结构

| 比较方式 | 期望值 | 说明 |
|---|---|---|
| 类型是 | `字符串` / `数字` / `布尔` / `数组` / `对象` / `null` | 防止后端把数字改成字符串这类隐蔽改动 |
| 必含字段 | `id,name,status` | 检查对象里这些 key 都在 |
| 是有效JSON | 不填 | 一般配 `响应文本` 用 |

### 数组 / 集合

| 比较方式 | 期望值 | 说明 |
|---|---|---|
| 长度等于 / 长度大于 / 长度小于 | `0` | 列表接口必备 |
| 属于 / 不属于 | `success,ok` | 枚举值校验，逗号分隔 |
| 包含元素 / 不包含元素 | `CP0002` | 配 `$.data.list[*].couponNo` 这种整列路径用 |
| 每项都不为空 | 不填 | 整列不能有空值 |
| 每项都含字段 | `id,name` | 每条记录字段齐全 |
| 无重复 | 不填 | 主键去重，配整列路径 |
| 升序 / 降序 | 排序字段名（数组里是对象时填，如 `id`） | 排序接口校验 |

### 与上次比较（重点，见第四节）

较上次增加 / 较上次减少 / 较上次不变 / 较上次变化 / 较上次变化不超过。

---

## 四、不用反复改期望值的三种写法

### 写法 1：和上一次执行比（领券、扣库存最适合）

券批次一共 10 张，每跑一次少一张。**不要写死「等于 9」**，写：

```
目标：$.data.remain    比较方式：较上次减少    期望值：1
```

- 第 1 次执行：没有上次数据，记为基线（提示「首次执行，记录基线 10」），算通过
- 第 2 次：10 → 9，通过
- 第 3 次：9 → 8，通过
- 某次变成 9 → 7：报「上次 9 → 本次 7（变化 -2），期望减少1」，判为不通过

基线存在执行结果里。清空执行结果后，下次执行会重新记基线。

同组还有：

- `较上次增加 1`：下单数、积分累计
- `较上次不变`：查询接口，跑两次结果应该一样（幂等校验）
- `较上次变化`：只要变了就算对，比如更新时间
- `较上次变化不超过 5`：允许波动的场景，比如在线人数

### 写法 2：和变量比（组合场景里最准）

在组合场景里，第一步先查一次余量并提取变量：

```
提取变量：before=$.data.remain
```

第二步领券，第三步再查余量，断言写：

```
目标：$.data.remain    比较方式：等于    期望值：${before}-1
```

期望值里支持 `${变量名}` 和四则运算（`+ - * / ( )`）。这种写法比「较上次」更严谨，
因为基线是本次执行现查的，不依赖历史。

### 写法 3：只校验规律，不校验具体值

券号每次都不一样，就别断言具体值，断言格式：

```
$.data.couponNo    正则匹配    ^CP\d{4}$
$.data.createTime  正则匹配    ^\d{4}-\d{2}-\d{2}
$.data.list        长度大于    0
$.data.total       类型是      数字
```

## 五、断言库（点「常用断言」一键添加）

| 分组 | 包含的断言 |
|---|---|
| 接口健康检查 | 状态码=200、`$.code`=0、`$.data` 不为空、耗时<3000（仅警告） |
| 列表 / 分页接口 | list 类型是数组、长度大于 0、total 类型是数字、`list[*].id` 无重复 |
| 领券 / 库存 | `$.data.remain` 较上次减少 1 |
| 字段结构校验 | `$.data` 必含字段、`$.data.list` 每项都含字段 |
| 异常 / 反向用例 | `$.code` 不等于 0、`$.msg` 包含错误文案、`$.data` 为空 |

加完再按自己接口改路径即可。

---

## 六、级别：必须通过 vs 仅警告

- **必须通过**：不满足 → 这条用例判为不符合预期，列表整行标红
- **仅警告**：不满足 → 只在结果里标 ⚠，**不影响整体结论**

典型用法：耗时、响应大小这类性能指标设成「仅警告」，避免测试环境偶尔抖动就把用例判失败。

执行完状态栏会汇总：`断言 通过 12 / 失败 1 / 警告 2`。

---

## 七、结果在哪看

| 位置 | 显示 |
|---|---|
| 列表「最近结果」列 | `成功 200 · 断言不通过1条`（整行标红）/ `断言通过(警告1)` |
| 查看结果窗口 | 每条断言的 √ / × / ⚠、期望值、实际值、失败原因 |
| 执行日志 | 实时打印失败的断言 |
| 导出 Excel | Sheet1 末尾两列；Sheet2 的「是否符合预期」列 |

导出的两列：

- **预期结果内容**：断言配置，每行 `目标 [比较方式] 期望值 @警告    # 备注`，行首 `#` 表示停用
- **是否符合预期**：最近一次的结论 + 每条明细

这两列在 Excel 里直接改也有效，重新导入就生效。

## 八、组合场景里的断言

场景的每一步都会跑对应接口自己的断言。任何一步断言失败，整个场景判为不通过。

公共配置里有个开关：**「组合场景里断言失败就停止后续步骤」**。

- 不勾（默认）：某步断言失败仍继续跑后面的步骤，一次跑完看全部问题
- 勾上：某步断言失败立即停止该场景，适合「前置步骤失败后面没意义」的串联流程

## 九、几条实践建议

1. **每个接口至少两条**：`状态码 等于 200` + `$.code 等于 0`。很多线上问题就是 HTTP 200 但业务码非 0。
2. **别断言整个响应体相等**。接口加个字段你的用例就红了，改成断言关键字段 + 类型 + 结构。
3. **动态值断言规律，不断言具体值**：ID、券号、时间戳用正则或「不为空」「类型是」。
4. **备注写清楚为什么**。三个月后你不会记得为什么断言 `status` 等于 2。
5. **反向用例同样要断言**。参数非法时应该返回什么错误码、什么文案、data 是不是空，都值得固化下来。
6. **性能类用「仅警告」**，别让环境抖动污染测试结论。
7. **改完先「试跑断言」**，确认路径写对、实际值是你想的那样，再正式执行。
